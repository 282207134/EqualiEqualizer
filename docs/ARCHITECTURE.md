# 架构与维护说明

## 设计原则

项目采用 Flutter 原生 Widget 实现参考稿，不把完整页面图片当作界面。封面、品牌标识及环绕插画来自 Pixso；唱片、光晕、旋钮、刻度和波形由 Flutter 绘制。交互控件具有语义标签，图标按钮提供提示和至少 44 逻辑像素的点击区域。

按 `core / data / features / ui` 组织代码，保持单向数据流。`ChangeNotifier + InheritedNotifier` 足以覆盖此规模的本地音乐应用，避免额外引入路由、依赖注入、状态管理框架。

## 模块职责

| 模块 | 职责 | 不承担的职责 |
| --- | --- | --- |
| `ui` | 设计 Token、拟物容器、按钮、封面、页头、输入框和弹层 | 数据存储、解码 |
| `features/library` | 音乐库呈现、搜索输入、歌单编辑、选择文件、传输页面 | 原生音效实现 |
| `features/player` | 播放 UI、音效参数输入、可视化绘制 | 伪造播放进度 |
| `features/account` | 本地资料表单、账号交互演示 | 云端身份认证 |
| `AppController` | 管理歌单、收藏、搜索历史、资料，触发状态保存 | 音频解码 |
| `AudioController` | 播放引擎生命周期、播放队列、进度监听、音效桥接 | 页面导航 |
| `StateStore` | 版本化状态读写接口 | 音频二进制存储 |
| `media_files` | 应用私有目录中的音频持久化 | 系统全盘扫描 |
| `WifiTransfer` | 页面存续期间的局域网上传服务 | 常驻服务器、云端中转 |
| Android `MainActivity` | 将音效绑定到 just_audio 的 Audio Session | 全局系统均衡器 |

## 状态与数据模型

`Track` 保存歌曲 ID、标题、作者、封面资源名、来源 URI 和是否为用户导入。目录中保留设计稿的 12 条音乐信息，源音频映射到 3 段随包合成示例。

`Playlist` 只保存有序的 Track ID，不复制歌曲对象。增加歌曲时过滤未知 ID 并去重；重排采用 Flutter `onReorderItem` 已计算的最终索引；删除上传歌曲时清理相关歌单、收藏、历史和播放队列。

`SoundSettings` 保存音量、5 个增益、预设名、均衡器开关、低音、虚拟器和空间拓宽参数。读取时限制数值范围，避免无效本地状态导致滑块越界。

`AppController` 通过 `AppScope` 向下提供。页面依赖状态并提交操作；状态改变后通知界面，250 ms 防抖合并保存。写入使用串行 Future 链，避免快速点击导致旧状态覆盖新状态。应用离开前额外触发保存。

播放进度直接来自 `just_audio` 的流，播放器只监听 `AudioController`，进度更新不触发整个音乐库的持久化。

## 本地存储

- 状态键：`equali.state.v1`，JSON 中带 `version: 1`。
- 保存内容：歌单、导入歌曲元数据、收藏、历史、资料、会话记忆状态和音效参数。
- 音频文件：使用 `path_provider` 获取应用 Documents 目录，存放于 `audio/` 子目录。
- 密码与验证码：不持久化；验证码为明确标注的本地演示值。
- 错误反馈：损坏或无法读取的存储回退到可用的默认目录；保存失败展示提示，不把读取失败解释为空数据。
- 卸载应用或清除应用数据会移除本地音乐库和导入的私有文件。

## 播放与音效链路

1. 歌曲点击交给 `AudioController.play`，建立或沿用队列。
2. `just_audio` 加载 Asset 或 File URI，真实解码并回报时长、状态和位置。
3. Android Audio Session ID 到达后，通过 `equali/audio_effects` 通道请求 `attach`。
4. Kotlin 独立尝试创建 Equalizer、BassBoost 和 Virtualizer，并回传设备能力。
5. `update` 把 60 / 230 / 910 / 3600 / 14000 Hz 的五个设计频段映射到硬件最近的频段，并按设备范围限制增益。
6. 更换会话前释放旧音效，Activity 销毁时再次释放，避免累积原生对象。

低音和虚拟器各自控制强度。3D Surround 启用时优先使用 `surround` 参数驱动同一个 Android Virtualizer；它是空间拓宽模式，不能视作独立 5.1/7.1 解码或真实头部追踪。

波形是固定的可交互视觉示意，已播放比例来自真实时间；不执行音频 FFT 或振幅分析。

## Wi-Fi 传输

服务仅在用户点击 Start transfer 后启动，监听 8765 端口，并生成 16 位随机路径令牌。网页用原始 POST body 传送文件，服务校验扩展名和 40 MB 大小上限，再交给文件存储层导入。未知路径返回 404，非支持扩展名返回 415，超限返回 413。

无需电脑安装软件，也没有云端中转。该服务为明文 HTTP，适用于可信局域网；关闭、返回或销毁传输页面后停止服务。设备的热点隔离、防火墙或访客网络可能阻止互访。

模拟器的 `10.0.2.15` 地址通常无法从宿主机直接访问。可在测试期间转发端口：

```sh
adb forward tcp:8765 tcp:8765
```

然后保留应用显示的令牌，将 URL 主机替换为 `127.0.0.1`。真实手机同网访问不需要此步骤。

## 路由与交互

使用 `Navigator` 和统一的 `openPage` 实现短距离淡入/滑入。菜单、添加歌曲、新歌单及重命名通过统一底部弹层呈现。删除操作在应用内确认，取消不修改数据；添加歌曲在 Done 后统一提交。

登录、注册、找回密码、验证码、重置密码复用一个带阶段枚举的表单组件，减少重复布局。页面明确显示本地预览性质，社交入口只说明尚未配置身份提供方。

## 平台适配

| 平台 | 当前实现 |
| --- | --- |
| Android | 主交付平台；播放、文件导入、私有文件保存、局域网上传和设备音效。 |
| iOS | 工程与基础功能代码已准备；最低 iOS 14，提供局域网用途说明；原生音效通道不调用，需 macOS/Xcode 构建验证。 |
| Web | 可以浏览 UI 和播放打包音乐；文件持久导入和本机监听服务的条件导入分支给出移动端提示，原生均衡器提示能力边界。 |

## 后续扩展位置

- 云端音乐库：在 `data` 层添加 Repository，将远端 DTO 转换为现有 Track/Playlist。
- 真实认证：以服务替换账号表单的本地提交逻辑；凭证应进入系统安全存储，不能写入当前偏好存储。
- 背景播放/锁屏控制：在播放层接入系统媒体服务，UI 和歌单结构无需重写。
- 元数据/真实波形：在导入阶段解析标签和振幅数据，替换 `Waveform` 的固定样式数据。
- iOS/Web DSP：为 `AudioController` 添加各平台处理实现，保留声音参数模型和面板。

## 精简说明

已移除计数器样板与多余依赖，统一设计 Token、控件、路由动画、歌曲行、弹层和表单。平台差异由条件导入隔离；音频文件不放入 JSON，播放进度不触发磁盘写入。没有增加只转发单个方法的多层服务或冗余状态框架。
